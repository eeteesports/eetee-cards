# Owner Fix Card workflow

Logged-in card images open the same lazy-loaded Fix Card editor across public shop grids, team-bundle contents, card viewers, collection tiles, and known-image fallback surfaces. Public visitors receive no editor controls. Owners edit front/back crop, rotation, brightness, contrast, saturation and gamma and card metadata. Preview pixel adjustments share the server's implementation. Saving validates both image revisions and the metadata revision and commits images + metadata atomically. Existing card IDs, prices, allocations and Stripe order records are not changed by identity edits.

Public-catalog identity corrections persist in `storefront_card_edits` and are applied by shopCatalog; private notes, cost, value, collection and location are deliberately omitted from public serialization. Older Turso inventory cards also update their established `cards` columns. The native Scan library is not modified or synchronized by these website edits. A future Scan synchronization must reconcile these owner edits by stable copy ID rather than replace them during an export.

Image versions persist exact before bytes and corrected WebP bytes in `storefront_image_versions`; `storefront_image_current` selects the version in use. Raw source files are never overwritten. Original images load from the owned public CDN; production functions never bundle the scan library. Tests and local correction batches inject a local source loader. Only existing trusted Cloudinary URLs are fetched for legacy inventory images. Current private inventory images and all before/after comparisons require owner login; the public image endpoint accepts published catalog IDs only.

Manual saves automatically create/update Image Review results. There is no owner "mark done" action. Routine automatic corrections remain optional in the editor. Ambiguous geometry and Other requests retain the prior image and show Needs manual review. Processing claims, revision checks, and a timeout/retry state prevent duplicate or stale publication. Restore switches the active image back to its preceding version and retains all history. Geometry presets for the three initial owner requests are visually checked and keyed by the source's SHA-256 so they cannot run on a different image.

Validation: `node --test tests/*.test.mjs`, Next production build, isolated authenticated API flow, and browser save/reopen plus responsive review. Do not use a real Stripe checkout to test this workflow.
